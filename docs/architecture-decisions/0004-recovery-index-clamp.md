# ADR-0004: Recovery Index — clamp компонентов в [0, max]

- **Дата:** 2026-05-09
- **Статус:** accepted
- **Авторы:** Claude (одобрено Андреем)

## Контекст

Формула Recovery Index из ТЗ:
```
RI = (сон_часы / 8) * 35
   + (8 - abs(систолическое - 120) / 8) * 25
   + (энергия / 10) * 25
   + бонус_за_streak_check_in * 15
```
При экстремальных значениях (давление 200, сон 12 часов) формула даёт
отрицательные / выходящие за 100 значения. Это противоречит обещанию
"индекс 0–100".

Также: ТЗ-формула двусмысленна по приоритету операций — `8 - abs(сист-120) / 8`
может означать `8 - (abs(сист-120) / 8)` или `(8 - abs(сист-120)) / 8`.

## Решение

Каждая компонента clamp в [0, max]:
- `sleep` ∈ [0, 35]
- `bp` ∈ [0, 25]
- `energy` ∈ [0, 25]
- `streak_bonus` ∈ [0, 15]

Финальный RI = sum(components), всегда ∈ [0, 100].

Интерпретация формулы давления (выбор приоритета операций): `8 - abs(сист-120)/8`,
затем нормализуется к 25 баллам через `max(0, score) / 8 * 25`. Это даёт:
- При сист=120: 8 → 25 баллов
- При сист=160: 8 - 5 = 3 → 9.4 балла
- При сист=200: 8 - 10 = -2 → clamp до 0 → 0 баллов
- При сист=80 (гипотония): 8 - 5 = 3 → 9.4 балла (симметрично)

Стрик: `min(streak_days, 7) / 7 * 15` — стрики >7 дней не дают доп. бонус
(защита от gaming).

## Альтернативы

1. **Без clamp** — отвергнуто: отрицательные компоненты ломают UX.
2. **Использовать готовый Whoop-алгоритм** — недоступен (proprietary).
3. **Заменить формулу на ML-модель** — отвергнуто на MVP: нужно разметить данные.

## Последствия

**Плюсы:**
- Гарантированно RI ∈ [0, 100], можно отображать в UI как progress bar.
- Не зависит от LLM (детерминированно, тестируется юнит-тестами).

**Минусы:**
- Реальный пользователь с давлением 90/60 (норма для худощавых) получит
  9.4 балла из 25, что может быть неинтуитивно. В v2.0 нужно учесть
  возраст / пол через персонализированный baseline.
