# ADR-0001: Monorepo layout

- **Дата:** 2026-05-09
- **Статус:** accepted
- **Авторы:** Андрей, Claude

## Контекст

Нужно решить структуру репозитория. Варианты: monorepo (всё в одном репо) vs
multirepo (бэкенд / фронтенд / инфра отдельно). У нас будет:
Python-бэкенд + React Mini App / PWA + Capacitor APK + миграции БД +
эвал-сюита Censor + промпты агентов + ML-скрипты сидинга.

## Решение

**Monorepo:** один репозиторий `bioarchitect` со структурой Modular Monolith
(см. Приложение А ТЗ). Фронтенд лежит в `src/miniapp/` внутри того же
репозитория.

## Альтернативы

1. **Multirepo (3-4 репозитория)** — отвергнуто:
   - Кросс-репо изменения (новый эндпоинт API + UI для него) требуют PR в 2-3 репо.
   - Усложняет CI: матрица версий.
   - Андрей — single developer, оверхед не оправдан.
2. **Polyrepo с git submodules** — отвергнуто, submodules сложны и непрактичны.

## Последствия

**Плюсы:**
- Единый CI, одна точка правды.
- Атомарные коммиты "бэк + фронт".
- Простой `make dev` поднимает весь стек.

**Минусы:**
- Размер репо растёт (особенно с node_modules в Capacitor — частично решается `.gitignore`).
- Чёткие границы между Python и TS требуют дисциплины (закрепляем через
  `src/miniapp/` как изолированный TS-проект со своим `package.json` и `tsconfig`).
