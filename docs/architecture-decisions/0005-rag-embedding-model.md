# ADR-0005: Embedding-модель для RAG

- **Дата:** 2026-05-09
- **Статус:** proposed (open — решение в спринте 9)
- **Авторы:** Claude

## Контекст

ТЗ запрещает OpenAI API. Anthropic не предоставляет embedding API. RAG-агент
должен индексировать ~30-100 статей и искать по pgvector. Нужна embedding-модель.

## Альтернативы

1. **Voyage AI `voyage-3-lite`** ($0.02 / 1M токенов):
   - + EU-region available.
   - + Высокое качество для multilingual (RU/EN/PL/DE).
   - − Очередной vendor (но единичный API call в момент индексации, не на каждый запрос пользователя).

2. **`bge-m3` self-hosted через `sentence-transformers`** (бесплатно):
   - + Полностью бесплатно.
   - + Multilingual (включая RU/PL/DE).
   - − Требует +1.5GB RAM на VPS (не критично на Hetzner CPX31 8GB).
   - − Замедляет индексацию (CPU-only).

3. **`text-embedding-3-large` через OpenAI** — **запрещено политикой проекта**.

4. **Cohere `embed-multilingual-v3.0`** ($0.10 / 1M токенов):
   - + Хорошее качество.
   - − Серверы CA/US, не идеально для GDPR.

## Решение

**Не принято.** Откладывается до спринта 9 (когда RAG Agent дойдёт до реализации).
По умолчанию идём с `bge-m3` self-hosted (опция 2) — бесплатно и без vendor-локина;
если качество недостаточно, переключаемся на Voyage AI.

## Последствия

В спринте 1-8 RAG не используется, поэтому решение не блокирующее.
Перед спринтом 9 принимаем финальное решение и фиксируем в этом ADR
(переводим из proposed → accepted).
